# 新闻采集工具选型与使用

选择 Crawl4AI 0.9.5，作为本项目现有 HTTP 抓取的浏览器补充。比较依据是上游项目文档和三篇真实新闻的试抓；未进行完整依赖安全审计，也未实测 Firecrawl、Scrapy 的速度。

| 工具 | 对本项目的适用性 | 成本与维护 | 结论 |
|---|---|---|---|
| [Crawl4AI](https://github.com/unclecode/crawl4ai) | 本地 Chromium 渲染动态文章、提取文本与 Markdown，适合每日跨国家、多媒体网站的小批量采料 | 本地使用无需云 API 密钥；需要浏览器和较多 Python 依赖 | 当前首选，已接入 |
| [Firecrawl](https://github.com/firecrawl/firecrawl) | 托管 API 可集中完成抓取与正文提取，适合日后需要托管服务的情况 | 托管版需要密钥、额度；自托管需要额外服务维护；主项目 AGPL-3.0，部分 SDK 为 MIT | 后续备选，本轮未安装 |
| [Scrapy](https://github.com/scrapy/scrapy) | 适合长期维护固定网站、分页、增量采集及结构化字段 | 需编写站点规则；JavaScript 页面通常另配渲染组件 | 固定信源规模扩大后再考虑，本轮未安装 |

## 实际接入

主环境 `.venv` 保留现有 PDF、历史读取、事实矩阵和质量检查。采集依赖安装在独立 `.venv-crawler`，浏览器放在 `.cache/ms-playwright`，避免依赖升级影响主环境。未配置云服务、LLM 提取或额外账户。

调用链：`brief.py fetch / fetch-batch` → `crawler.capture_many` → HTTP → 有失败或访问警示时调用独立进程 `crawler_worker.py` → Crawl4AI → 归档证据。`ingest.capture_url` 的默认 HTTP 接口保留兼容。

每批 1—50 个 URL，全局并发 1—4，默认 3；同一主机串行。浏览器模式遵守 robots 检查，阻止非 GET/HEAD/OPTIONS 请求以及图片、媒体、字体，不执行点击、登录或提交，不移除付费墙。网站仍可能返回验证码、拒绝访问或不完整正文，此时必须换公开可信来源。

## 命令

恢复环境：

```powershell
powershell -File scripts/setup-crawler.ps1
```

默认自动补抓：

```powershell
.venv\Scripts\python.exe scripts/brief.py fetch "https://example.org/article" --engine auto
```

网页有较长静态导航但正文依赖 JavaScript 时，短文本检查未必能识别，采编人员应读正文后显式补抓：

```powershell
.venv\Scripts\python.exe scripts/brief.py fetch "https://example.org/article" --engine browser
```

批量文件须为 UTF-8 JSON 字符串数组，例如 `["https://example.org/article-a", "https://example.net/article-b"]`，随后运行：

```powershell
.venv\Scripts\python.exe scripts/brief.py fetch-batch urls.json --engine auto --concurrency 3
```

正常结果为 `CAPTURED_NOT_VERIFIED`；访问警示、错误或回退失败为 `INCOMPLETE`，CLI 返回非零。错误不会自动替换成“已核实”。抓取日志位于 `logs/日期/capture/`。

## 证据与常见问题

浏览器证据位于 `input/web/<内容标识>/`，包含 `response.html`（渲染后 DOM，`raw_kind=rendered_dom`）、可取得时的 `original_document.html`（实际原始文档响应）、`text.txt`、`article.md`、`artifact.json`。各文件保存哈希、来源和采集时间。再次抓取相同内容复用已有证据，保留矩阵绑定；内容改变则另存。

正文提取可能漏掉日期、表格或背景，也可能保留导航。必须阅读原文和页面上下文，核对主体、动作、对象、地点、日期、数字、阶段；`NOT_PERFORMED` 表示工具没有执行事实核验。不要把 HTML 可访问、正文较长、HTTP 200 或抓取无警示当作核验通过。文章发布日期仍不能替代实际事件日期。

本工具加快的是文章获取和证据归档，不能代替 21 国逐国检索、Google 只读 30 天语义查重、本地近两日正式稿比较、双语核对、逐条复核、全稿 QA 或人工终审。生产环境采用版本锁定、同主机限流、保留原证据、失败换源；升级后重新跑下面的测试，连续观察真实日报耗时和退回情况。

## 已实际验证的范围

2026-10-27，两个环境 `pip check` 通过，19 项单元/回归测试通过。本地动态页集成测试验证动态正文、auto 回退、POST 拦截、原始响应与 DOM 哈希、付费墙、404、robots 禁止访问、跳转及批量部分失败的 CLI 退出码。完整结果见 `logs/2026-10-27/crawler-research/verification.json`。

三篇真实页面（盖世、腾讯、Business Facilities）均取得 HTTP 与浏览器证据。本次 HTTP 批量约 2.69 秒、浏览器约 7.80 秒。逐段看腾讯文本，两者新闻主体内容相同，浏览器多出的文本主要是导航，不能用字符增长声称正文更完整；Business Facilities 导航文本减少。这是小样本操作验证，不能推出普遍提速比例。明细见 `logs/2026-10-27/crawler-research/live-validation.json`。

建议复验：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe tests/crawler_smoke.py
```
